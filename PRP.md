0. ROLE & EXECUTION DIRECTIVE

You are an expert product engineer, UI/UX designer, interaction designer, and frontend architect.

Your task is to design and build a polished showcase website for Kohinoor Enterprise, Bhiwandi.

This is not an e-commerce checkout website.

The website's primary purpose is:

Someone discovers Kohinoor Enterprise through Instagram → visits the website → understands that Kohinoor has a wide variety of products from recognizable brands at attractive/value-focused prices → explores relevant products → becomes interested → contacts Kohinoor on WhatsApp/call or decides to physically visit the store.

The website should feel like a combination of:

a premium product showroom
an editorial product catalogue
a modern retail brand website
a visually rich product-discovery experience

It must NOT feel like:

a generic e-commerce template
a basic Shopify store
an Amazon clone
a boring product grid
a corporate business website
an over-designed luxury furniture website
a dark-tech website

The business is value-oriented, so the design must balance:

premium presentation + accessibility + street-smart confidence + strong value perception.

5. CORE PRODUCT CONCEPT

This website is fundamentally a digital showroom.

It exists because Kohinoor's social-media marketing creates discovery but creates a gap:

Someone sees a product on Instagram, becomes interested, but may not want to travel to the shop simply to discover what is available.

The website solves that gap.

It gives the customer:

“Let me see what they have before I decide to visit.”

Therefore the website should communicate:

Emotional realization #1

“Damn, they have everything.”

Emotional realization #2

“And the prices/value seem really good.”

Then:

“I should visit the store.”

The website should progressively create those realizations rather than dumping hundreds of products onto the visitor.

51. JSON PERSISTENCE CONSIDERATION

Because this project intentionally avoids a database, do not pretend that a browser can permanently rewrite the deployed source JSON file if the deployment environment is read-only.

Implement the simplest practical architecture that supports the requested workflow.

Preferred approach:

JSON
 ↓
Application
 ↓
Admin API/server action
 ↓
JSON file update

if the chosen runtime/deployment environment permits server-side file writes.

If the environment cannot safely persist changes to the source filesystem, clearly isolate the persistence layer so it can later be replaced with a database/API without rewriting the UI.

Do not create fake “Save” functionality that appears successful but silently loses changes.
